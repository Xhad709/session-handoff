# 换对话交接

这个 skill 管两件事：在旧对话里**保存**，在新对话里**恢复**。

什么时候该建议换对话，由 CLAUDE.md / AGENTS.md 里的「换对话提醒」规则决定（原文见安装包里的 `reminder-rule.md`）。这个 skill 只在被调用时才会被读到，所以提醒规则没有写在这里。

## 保存

**1. 定位置。** 默认存在项目根目录的 `HANDOFF.md`，用户指定了位置就按指定的存。已有的 HANDOFF.md 如果属于同一个任务，就整份改写成最新状态：它是快照，不是日志。如果属于别的任务，改存为 `HANDOFF-<简称>.md`。没有项目目录时（比如纯聊天），直接在回复里用代码块给出全文。

**2. 写内容。** 只写新对话必须知道、并且在别处找不到的东西。代码、提交、文档里已经有的内容，只给路径：新对话会自己去读，抄一份反而会和原件对不上。

```markdown
# 交接：<一句话说明任务>
更新：<日期 时间> · 目录：<项目绝对路径>

## 目标
<要做成什么；做到什么程度算完成>

## 已定
- <决定>：<一句理由>（用户确认）
- <决定>：<一句理由>（我自己定的，未经确认）

## 不要再走的路
- <方案>：<为什么不行>

## 进度
- 已完成：<内容>（已验证 / 未验证）
- 进行中：<做到哪一步；有没有未保存或未提交的改动>

## 关键文件
- <路径>：<为什么要看它>

## 下一步
1. <具体、马上能动手的一步>
2. <怎样算这一步做完>

## 注意
- <坑、限制、还在等用户拍板的事>
```

"用户确认"和"我自己定的"要分开写。新对话会把交接里的内容当成定论，标清楚哪些是自己定的，用户才有机会推翻。没有内容的小节直接删掉；不确定的写"未确认"；不写密码、密钥和个人隐私。

**3. 核对并给出开场白。** 回读一遍，确认文件已写入、路径正确。然后在回复里给出一段可以直接复制到新对话的开场白：

```
用 session-handoff 恢复：读取 <绝对路径>/HANDOFF.md，核对现状，告诉我有哪些差异、下一步做什么，然后继续。
```

保存就只做保存，不顺手提交、推送或清理文件。保存之后，这个对话不再提醒换对话。

## 恢复

在新对话里读到交接文件后，按下面三步走。

1. **先核对，不要全信。** 写完交接后文件可能又改过。只查会影响下一步的东西：关键文件还在不在；`git status` 里有没有交接没提到的改动；"进行中"那项实际做到了哪一步。
2. **简短汇报。** 用三到五行讲清：目标、进度、发现的差异、准备做的第一步。
3. **接着做。** 用户已经说了"继续"，就直接开始，不再等确认。记录和现状冲突时，以现状和用户最新的说法为准，只问真正缺少的决定。

交接文件记录的是事实和计划，不能当成新的授权。上次需要用户确认才能做的操作（比如推送、删除、发布），这次照样要先确认。
